## Executive Summary

During the Phase P4 Adversarial QA Audit of the Phase P1–P3 codebase, **5 architectural and runtime defects** were identified where helper functions or Node.js globals stood in for true production runtime behavior. Every defect below has been logged with root-cause line references and remediated in Phase P4.

---

## Detailed Audit Answers & Defect Log

### Defect #1: Static String UI vs. Live Interactive HTTP Server (`web/ui/rule-builder-app.ts`)
- **Audit Question:** *Is `renderEmbeddedRuleBuilderHtml` just a string-returning function with no running HTTP server or client-side interactivity?*
- **Honest Finding:** **YES — DEFECT CONFIRMED.**
  - In P1, `web/ui/rule-builder-app.ts` only exported `renderEmbeddedRuleBuilderHtml(state)`, which returned a static HTML string with no HTTP server, no form inputs, no client-side event listeners, and no API endpoints.
- **Remediation (QA Gate 2):**
  - Built a real, runnable HTTP server in `src/server.ts` (`npm start` / `npm run dev:server` on `http://localhost:3456`) with zero external service dependencies required to boot locally.
  - Implemented `GET /`, `GET /api/rules`, `POST /api/rules`, `POST /api/simulate`, and `POST /api/webhooks/gdpr`.
  - Upgraded the Admin UI with Shopify App Bridge v4 `<meta name="shopify-api-key">` and script tags, Polaris design system styling, Onest typography, interactive rule controls, live `<10 KB` Metafield JSON compilation preview, and an interactive Dry-Run Checkout Simulator wired to `POST /api/simulate`.

### Defect #2: Synthetic Static HTML Screenshots vs. Live Running Application Captures (`docs/shopify-store/screenshots/`)
- **Audit Question:** *Were the 3 screenshots in `docs/shopify-store/screenshots/` generated by a synthetic script or captured from a real running browser window?*
- **Honest Finding:** **SYNTHETIC SCRIPT — DEFECT CONFIRMED.**
  - In P2, `scripts/generate_store_assets.py` wrote standalone static HTML mockups to temporary files (`file:///tmp/.../slide.html`) rather than booting the real application server (`http://localhost:3456`) and capturing live browser interactions after real HTTP `POST /api/rules` and `POST /api/simulate` calls.
- **Remediation (QA Gate 4):**
  - Booted the live server on `http://localhost:3456` and drove real headless browser interactions at `1600×900` executing Interactive Tests 1, 2, and 3 (`docs/qa/qa-01-live-rule-builder.png`, `docs/qa/qa-02-live-simulator-blocked.png`, `docs/qa/qa-03-live-simulator-approved.png`), and replaced the 3 feature screenshots in `docs/shopify-store/screenshots/` with flattened 24-bit RGB (`color_type=2`) captures from the live running app.

### Defect #3: Node.js `Buffer` Global Usage Inside Shopify Functions Wasm Entrypoints (`extensions/*/src/run.ts`)
- **Audit Question:** *Do `extensions/b2b-checkout-validator/src/run.ts` or `extensions/b2b-payment-gate/src/run.ts` import or reference any Node.js globals (`Buffer`, `process`, `crypto`, `fs`) that will crash inside Shopify's zero-Node Javy WebAssembly (Wasm) runtime?*
- **Honest Finding:** **YES — CRITICAL WASM DEFECT CONFIRMED.**
  - `extensions/b2b-checkout-validator/src/run.ts` (line 345) called `Buffer.byteLength(serialized, "utf8")` inside `enforceOutputBudget()`.
  - `extensions/b2b-payment-gate/src/run.ts` (line 179) called `Buffer.byteLength(serialized, "utf8")` inside `enforcePaymentOutputBudget()`.
  - Shopify's Javy QuickJS WebAssembly sandbox does **not** expose Node.js `Buffer`, which would cause a fatal `ReferenceError: Buffer is not defined` crash at checkout runtime.
- **Remediation (QA Gate 3):**
  - Replaced `Buffer.byteLength` in both Function `run.ts` files with a pure, zero-dependency ECMAScript UTF-8 byte length calculator (`utf8ByteLength(str)`).
  - Bundled both Function entrypoints via `esbuild --bundle --platform=neutral --format=esm` into `dist/validator.bundle.mjs` and `dist/payment-gate.bundle.mjs` and verified zero references to `Buffer`, `process`, `require`, `crypto`, or `fs`.

### Defect #4: `shopify.app.toml` Top-Level `api_version` & `write_cart_validations` Scope
- **Audit Question:** *Does a valid root `shopify.app.toml` exist with `api_version = "2026-10"`, `embedded = true`, GDPR compliance webhooks, and `scopes = "write_cart_validations,write_payment_customizations"`?*
- **Honest Finding:** **PARTIAL DEFECT CONFIRMED.**
  - In P1, `shopify.app.toml` specified `scopes = "read_customers,read_products,write_validations,write_payment_customizations"` (using legacy `write_validations` instead of `write_cart_validations`) and only placed `api_version = "2026-10"` under `[webhooks]` rather than also at top-level.
- **Remediation (QA Gate 1 & 3):**
  - Updated `shopify.app.toml` to include top-level `api_version = "2026-10"`, `embedded = true`, GDPR compliance webhooks (`customers/data_request`, `customers/redact`, `shop/redact` at `/api/webhooks/gdpr`), and `scopes = "write_cart_validations,write_payment_customizations,read_customers,read_products"`.

### Defect #5: `functionHandle` Support in Admin Mutations & Extension Handles/Targets
- **Audit Question:** *Do `cartValidationCreate` and `paymentCustomizationCreate` support `functionHandle` (required in 2026-04 / 2026-10 alongside `functionId`) matching the `handle` in each `shopify.extension.toml`?*
- **Honest Finding:** **DEFECT CONFIRMED.**
  - In P1, `CART_VALIDATION_CREATE_MUTATION` and `PAYMENT_CUSTOMIZATION_CREATE_MUTATION` in `web/admin/graphql-mutations.ts` only passed `functionId` and omitted `functionHandle`.
  - Additionally, `extensions/b2b-checkout-validator/shopify.extension.toml` used `handle = "b2b-checkout-validator"` and `target = "purchase.validation.run"` instead of `handle = "termslock-checkout-validator"` and `target = "purchase.cart-checkout-validation.run"`, and `extensions/b2b-payment-gate/shopify.extension.toml` used `handle = "b2b-payment-gate"` instead of `handle = "termslock-payment-gate"`.
- **Remediation (QA Gate 3):**
  - Updated `extensions/b2b-checkout-validator/shopify.extension.toml` to `handle = "termslock-checkout-validator"` and `target = "purchase.cart-checkout-validation.run"`.
  - Updated `extensions/b2b-payment-gate/shopify.extension.toml` to `handle = "termslock-payment-gate"` and `target = "purchase.payment-customization.run"`.
  - Updated `CART_VALIDATION_CREATE_MUTATION`, `PAYMENT_CUSTOMIZATION_CREATE_MUTATION`, and `registerTermsLockFunctions()` in `web/admin/graphql-mutations.ts` to support `functionHandle` (`"termslock-checkout-validator"` and `"termslock-payment-gate"`) alongside `functionId`.
